3.4.- Conjuntos (V). Ordenando sus elementos

CC by-sa Joestape89

Para que una colección de tipo TreeSet pueda albergar objetos instancia de un determinado tipo o clase, estos deben ser "ordenables" o "comparables". Es decir, que debe existir para la clase un criterio claro y sin ambigüedad que indique, ante dos objetos cualesquiera instancias de esa clase, si uno es mayor o que otro o si son iguales. Esto significa que ante dos objetos siempre podremos saber cuál estaría antes que el otro (o cuál es menor que el otro), o bien si son iguales. Esto es imprescindible para poder crear un TreeSet que contenga objetos de una clase determinada.

Por ejemplo, podemos crear colecciones TreeSet de objetos Integer, String o Double, pues todas esas clases disponen de un criterio de comparación (implementan la interfaz Comparable). Del mismo modo sucedería si el TreeSet estuviera compuesto por objetos de tipo LocalDate o LocalTime, pues también disponen de criterio de comparación (también implementan la interfaz Comparable). Ahora bien, si los objetos que se intentan almacenar en la colección no tienen implementada la interfaz Comparable (no disponen de criterio de ordenación), se producirá un error de ejecución al intentar añadir un elemento en el  TreeSet.

Todos estos casos son válidos:

Set<Integer>    conjuntoOrdenado1 = new TreeSet<>();
conjuntoOrdenado1.add(1);

Set<Double>     conjuntoOrdenado2 = new TreeSet<>();
conjuntoOrdenado2.add(5.0);

Set<String>     conjuntoOrdenado3 = new TreeSet<>();
conjuntoOrdenado3.add("Juan");

Set<LocalDate>  conjuntoOrdenado4 = new TreeSet<>();
conjuntoOrdenado4.add(LocalDate.now());

Set<LocalTime>  conjuntoOrdenado5 = new TreeSet<>();
conjuntoOrdenado5.add (LocalTime.now());

Sin embargo, este otro caso producirá un error de ejecución al intentar añadir un objeto en la colección, pues la clase Rectangle no es "comparable" (no implementa la interfaz Comparable) y por tanto no es posible colocar un objeto Rectangle antes que otro (no existe criterio de comparación entre objetos instancia de la clase Rectangle):

Set<Rectangle>  conjuntoOrdenado6 = new TreeSet<>();
conjuntoOrdenado6.add(new Rectangle(100,200)); // Esto dará lugar a un error de ejecución

Si intentamos crear una colección de tipo TreeSet<T> y T es una clase cuyos objetos no son comparables (la clase no implementa la interfaz Comparable), cuando se intente añadir un objeto de tipo T a la colección, se producirá un error de ejecución.

Entonces, ¿no es posible crear un conjunto "ordenado" (colección TreeSet) de objetos de tipo Rectangle? La primera respuesta es no, pues la clase Rectangle no implementa la interfaz Comparable. Ahora bien, podríamos hacer una segunda pregunta: ¿es posible dotar a la clase Rectangle de un criterio de ordenación? La clase Rectangle ya está escrita y no implementa la interfaz Comparable, pero existe un segundo mecanismo para poder proporcionar criterios de ordenación: se trata de las clases "comparadoras".

Llamamos clases "comparadoras" a aquellas clases que implementan la interfaz Comparator. Esta interfaz obliga a codificar un método llamado compare, que es similar al método compareTo. Este mecanismo resulta útil para objetos que no tengan implementado ningún mecanismo de comparación (el caso de la clase Rectangle) o necesiten más de uno (por ejemplo, un producto comercial que es comparable por precio, nombre y fecha de caducidad).

Por defecto, los TreeSet ordenan sus elementos de forma ascendente, pero, ¿se podría cambiar el orden de ordenación?

Como ya sabemos, las colecciones de tipo TreeSet tienen un conjunto de operaciones adicionales, además de las que incluye por el hecho de ser un conjunto e implementar la interfaz Set, que permite entre otras cosas, cambiar la forma de ordenar los elementos. Esto es especialmente útil cuando el tipo de objeto que se almacena no es un simple número, sino algo más complejo (por ejemplo, un artículo o producto de una tienda.

TreeSet es capaz de ordenar sin problema objetos cuyas clases implementen la interfaz Comparable como son, por ejemplo, las clases que representan los tipos básicos (números, cadenas, fechas, etc.). Ahora bien, si la clase no ha implementado la interfaz Comparable por sí misma, habrá que indicar a la colección TreeSet cómo tiene que ordenar los elementos. Para ello debemos construir una clase "comparadora" que sea capaz de decirle cuándo un elemento va antes o después que otro, y cuándo son iguales. Para crear una clase "comparadora" de objetos de algún tipo disponemos la interfaz genérica java.util.Comparator<T>, usada en general en algoritmos de ordenación, como veremos más adelante.

Para crear una clase "comparadora" basta con una clase que implemente la interfaz Comparator. Dicha interfaz requiere de un único método que debe calcular si un objeto pasado por parámetro es mayor, menor o igual que otro del mismo tipo, también pasado como parámetro. Veamos un ejemplo general de cómo implementar un comparador para una hipotética clase "ObjetoComparable":

class ComparadorDeObjetos implements Comparator<ObjetoComparable> {
    public int compare(ObjetoComparable objeto1, ObjetoComparable objeto2) { ... }    
}

La interfaz Comparator obliga a implementar un único método, el método compare(), con dos parámetros: los dos elementos a comparar. Las reglas son sencillas, a la hora de personalizar dicho método:

  • Si el primer objeto (objeto1) se considera menor que el segundo (objeto2), debe devolver un número entero negativo.
  • Si el primer objeto (objeto1) se considera mayor que el segundo (objeto2), debe devolver un número entero positivo.
  • Si ambos son iguales, debe devolver 0. 

Te suena, ¿verdad? Es el mismo criterio que seguía el método compareTo() que usábamos para comparar dos String o que hemos visto en general a la hora de implementar la interfaz Comparable.

A veces, cuando el orden que deben tener los elementos es diferente al orden habitual (por ejemplo cuando ordenamos los números en orden inverso), la definición de antes, pensando en menor y mayor,  puede ser un poco liosa, así que es recomendable en tales casos pensar en términos de delante y detrás, o de antes y después, más o menos de la siguiente forma:

  • Si el primer objeto (objeto1) debe ir antes que el segundo objeto (objeto2), devolver entero negativo.
  • Si el primer objeto (objeto1) debe ir después que el segundo objeto (objeto2), devolver entero positivo.
  • Si ambos son iguales, debe devolver 0.

Una vez creado el comparador simplemente tenemos que pasarlo como parámetro en el momento de la creación al TreeSet, y los datos internamente mantendrán dicha ordenación:

Set<Objeto> conjunto=new TreeSet<ObjetoComparable>(new ComparadorDeObjetos());

Ejercicio resuelto

Una vez visto como funcionan las interfaces Comparable y Comparator, así como las clases comparadoras, vamos a trabajar con colecciones de tipo TreeSet que contengan objetos instancia de la siguiente clase:

class ObjetoComparable {
     public int a;
     public int b;
}

Los objetos de esta clase no son "aptos" para poder ser elementos de colecciones de tipo TreeSet, pues no existe ningún criterio definido para decidir, ante dos objetos de ese tipo, cuál de ellos es menor o mayor, o si son iguales. Es decir, si intentamos ejecutar las siguiente líneas de código:

ObjetoComparable objeto1 = new ObjetoComparable ();
objeto1.a = 1;
objeto1.b = 3;

Set<ObjetoComparable> conjunto = new TreeSet<>();
conjunto.add (objeto1); // Producirá un error de ejecución

Se producirá un error de ejecución al intentar añadir algún elemento a la colección  TreeSet llamada conjunto.

¿Cómo podemos arreglarlo?

Lo primero que necesitamos es algún criterio para poder comparar y colocar un elemento antes que otro. Se ha decidido que el criterio sea el siguiente: un elemento de tipo ObjetoComparable es mayor que otro si la suma de sus atributos es mayor.

Ahora que ya disponemos de un criterio, podemos plantearnos cómo implementarlo.

Para empezar, podríamos hacer que la clase ObjetoComparable implementara la interfaz Comparable. Esa sería la forma más sencilla, si es que tuviéramos la posibilidad de hacerlo (si la clase ObjetoComparable ha sido implementada por nosotros, tenemos acceso al código fuente para modificarlo y no va a suponer ningún problema de coherencia con el resto de código que utilice esta clase).

Parece fácil, ¿no? Se trataría simplemente de implementar el método CompareTo dentro de la clase ObjetoComparable siguiendo las directrices del criterio anterior. ¿Cómo lo harías?

Retroalimentación

En este caso, el "comparador" iría implícito en la propia clase ObjetoComparable al implementar la interfaz Comparable. Para ello habría que escribir el código correspondiente al método compareTo e incluir el "Implements Comparable" en la cabecera de la clase:

public class ObjetoComparable implements Comparable<ObjetoComparable> {

    public int a;
    public int b;

    @Override
    public int compareTo (ObjetoComparable objeto) {
        int resultado;
        int sumaThis = this.a + this.b;
        int sumaParametro = objeto.a + objeto.b;
        if (sumaThis < sumaParametro) { // El objeto es menor que el objeto que se pasa como parámetro
            resultado = -1;
        } else {
            if (sumaThis > sumaParametro) { // El objeto es mayor que le objeto que se pasa como parámetro
                resultado = 1;
            } else {
                resultado = 0;
            }
        }
        return resultado;
    }
}

Ahora bien, el método compareTo podría haberse simplificado mucho más haciendo simplemente una resta:

@Override
public int compareTo (ObjetoComparable objeto) {
    int resultado;
    int sumaThis = this.a + this.b;
    int sumaParametro = objeto.a + objeto.b;
    return sumaThis - SumaParametro;
}

E incluso podríamos simplificarlo más:

@Override
public int compareTo (ObjetoComparable objeto) {
    return (this.a + this.b) - (objeto.a + objeto.b);
}

Por tanto, el resultado final podría haber quedado en algo como:

public class ObjetoComparable implements Comparable<ObjetoComparable> {

    public int a;
    public int b;

    @Override
    public int compareTo (ObjetoComparable objeto) {
        return (this.a + this.b) - (objeto.a + objeto.b);
    }
}

En este caso no se producirá un error de ejecución al intentar añadir algún elemento de tipo ObjetoComparable a la colección TreeSet de objetos instancia de la clase ObjetoComparable.

Otra opción, en lugar de implementar la interfaz Comparable en la propia clase ObjetoComparable, podría ser implementar una clase "comparadora" de objetos de tipo ObjetoComparable que siga el criterio de comparación.

Para ello, habrá que implementar una clase llamada, por ejemplo, ComparadorDeObjetosComparables que implemente la interfaz Comparator (y codifique por tanto el método compare). ¿Te animas a intentarlo?

Retroalimentación

En este caso, habrá que escribir el código del método compare, que tendrá dos parámetros de tipo ObjetoComparable:

class ComparadorDeObjetosComparables implements Comparator<ObjetoComparable> {
    @Override
    public int compare(ObjetoComparable objeto1, ObjetoComparable objeto2){
         return (objeto1.a + objeto1.b) - (objeto2.a + objeto2.b);  
    }
}

Una vez que dispusiéramos de ese "comparador", bastaría con utilizarlo a la hora de crear la colección TreeSet de objetos de tipo ObjetoComparable:

ObjetoComparable objeto1 = new ObjetoComparable ();
objeto1.a = 1;
objeto1.b = 3;

Set<ObjetoComparable> conjunto = new TreeSet<>( new ComparadorDeObjetosComparables() ); // Al crear la colección TreeSet de objetos ObjetoComparable, le proporcionamos un criterio de comparación
conjunto.add (objeto1); // No producirá un error de ejecución, pues existe un criterio de comparación para poder ordenar los elementos

En este caso no se producirá un error de ejecución al intentar añadir algún elemento a la colección  TreeSet llamada conjunto.

La necesidad de utilizar este segundo mecanismo, algo más complicado, puede deberse a varias razones. Por ejemplo:

  1. que no sea posible modificar el código dela clase ObjetoComparable para que implemente la interfaz Comparable;
  2. que queramos implementar distintos tipos de "comparadores", es decir, distintos tipos de criterios para comparar objetos de tipo ObjetoComparable. Con este mecanismo de clases "comparadoras" podremos implementar todos lo "comparadores" que necesitemos. Por ejemplo: que el criterio de comparación sea la suma de los parámetros, que el criterio sea la comparación del primer parámetro, que el criterio sea la suma del número de cifras de ambos parámetros, que el criterio sea la suma de los parámetros pero considerando el orden inverso (un elemento se coloca antes cuanto menor sea la suma), etc. Y así tantos criterios como se nos puedan ocurrir o necesitemos.

Imaginemos que más adelante apareciera un nuevo posible criterio de ordenación para objetos de la clase ObjetoComparable. En tal caso bastaría con implementar una nueva clase "comparadora" y utilizarla a la hora crear una colección TreeSet para indicar que ese es el criterio de ordenación para esa colección.

Supongamos que ese nuevo "comparador" se ha implementado en una clase llamada ComparadorObjetosPorCifras. ¿cómo crearías una colección de objetos de tipo ObjetoComparable utilizando este nuevo criterio?

Retroalimentación

Bastaría con pasar una instancia de la clase "comparadora" ComparadorObjetosPorCifras como parámetro en el constructor del TreeSe:

Set<ObjetoComparable> conjunto = new TreeSet<>( new ComparadorObjetosPorCifras() ); // Se proporciona un nuevo criterio de comparación
